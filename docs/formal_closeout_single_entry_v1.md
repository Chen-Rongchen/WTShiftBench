# 当前正式收口唯一入口 v1

## 1. 文档定位

这份文档只做一件事：

**把当前项目的唯一主线、当前未闭环事项、禁写边界与默认阅读顺序压成一页总入口。**

它不引入新结果，也不替代更细的结果文档；它只负责把当前正式口径钉死。

## 2. 当前项目一句话

当前项目已经进入**主张治理稳定化阶段**：主要结果边界已被治理清楚，当前真正缺的不是新 entrant，而是把比较、敏感性、混杂、最终边界收成 manuscript-ready wording，并继续保持 discovery 为 `gated_downstream_layer`。

## 3. 当前唯一主线

当前默认主线固定为：

1. 比较
2. 敏感性
3. 混杂
4. 最终边界
5. discovery 继续 gated

这五项之外，当前都不应被写成默认下一步。

## 4. 当前最稳的正式结论

当前可以稳定保留的正式结论只有这几条：

- `GEARS` 在 HCC primary adjudication 中应写成 `architecture trade-off diagnosis`
- `shared_mean_baseline` 仍是 backbone 更强的 primary reference
- 复杂 entrant 当前不能稳定胜过 baseline，最稳的解释是 shared canonical backbone 较强，而 entrant 的额外优势更偏 `separation / deviation`
- `truth–DepMap bridge` 可保留，但必须按分层证据书写
- `PFDN5` 最多只能写成 `primary_but_qualified`
- `PMF1 / PRPF6 / ZNF131` 当前只能写成 `supporting_only`
- `transcription / chromatin` 最多只能写成 `primary_axis_but_qualified`
- `Dixit/K562` 只能写成 `supplementary external structure replication`
- discovery 当前只能写成 `gated_downstream_layer`

## 5. 当前真正还没 fully closed 的

- `sensitivity full closure` 仍未 fully closed
- `covariate closure` 仍未 fully closed
- `final claim matrix -> manuscript wording` 仍需持续同步
- discovery 仍未进入 formal deliverable

这些事项的关键边界是：

- 不是分析框架缺位
- sensitivity 的 formal interval 现在已可引用
- 但混杂线仍受实验设计元数据上限约束

更准确地说：

- covariate 线现在是五条轴已落盘、风险已治理进边界；其中 `barcode_gem_group` 已固定为 `design-proxy axis`，但还没到 `fully deconfounded`
- sensitivity 线现在是 `formal interval` 已可引用，但 full closure 仍被 covariate 未闭环卡住
- `final claim matrix -> manuscript wording` 是持续同步动作，不是一次性结束
- discovery 仍只能保留在 `gated_downstream_layer`，还不能写成 formal deliverable

这也意味着，当前阶段默认应接受：

- `design-proxy` 是本阶段最终口径
- covariate 线不会再等到 `fully clean` 才开写
- 论文将带着这条 limitation 写
- 是否开始写论文，取决于文稿与边界是否稳定，而不是数据是否完美

## 6. 当前明确不能写什么

- `model recovery has been demonstrated`
- `GEARS` 已整体压过 `shared_mean_baseline`
- stable anchors 已被 fully deconfounded
- `barcode_gem_group` 已被解析为单个 `MH00x` run-level covariate
- 多数 axis 已完成同等级正式闭环
- `Dixit/K562` 与 HCC 构成对称 primary conclusion
- discovery 已成为当前正式主交付
- discovery 已进入 formal deliverable
- `Stage 2 complete`
- `Stage 3 complete`

## 7. baseline gap 的默认后续口径

后续如果还要推进 baseline-vs-model gap，默认不再追问泛泛的“模型为什么打不过 baseline”，而只追问两个更小的问题：

1. `baseline winner` 是否主要由 shared backbone objective 决定
2. entrant 的额外能力是否稳定落在 `separation / deviation` 而不是 backbone 上

在这两个问题进一步收紧前，biology-facing explanation 仍只应保留为 plausible interpretation。
