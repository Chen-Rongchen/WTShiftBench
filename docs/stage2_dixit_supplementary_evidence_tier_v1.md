# Stage 2 Dixit/K562 supplementary evidence tier v1

## 1. 文档定位

这份文档只做一件事：

**把 `Dixit/K562` 这条 supplementary external structure replication 线，压成可直接进入主文档的 evidence-tiered interpretation。**

它不把 `K562` 升格为与 `HCC38 / HCC1143` 并列的 primary conclusion，也不把局部可解释 axis 写成与 HCC 同等级的 frozen architecture。

## 2. 当前最稳的总体结论

`Dixit/K562` 当前最稳的角色不是“第二主战场”，而是：

**在 supplementary 层面确认 architecture existence，并提供一个 context-specific 的外部结构复现对象。**

更具体地说，当前证据支持三件事：

- `K562` 中同样可以观察到 `canonical backbone`
- `K562` 中同样可以观察到 `shift-excess`
- 但其 dominant backbone macro class 与 HCC 不同，因此当前更适合写成 `context-specific supplementary replication`

因此，`Dixit/K562` 支持的是“bridge architecture 具有外部可复制性”，而不是“`K562` 与 HCC 共享同一个主线 architecture”。

更进一步说，当前这条线最稳的认识论位置是：

- `architecture-level replication`
- `structure-level transferability`

而不是：

- `model generalization`
- `object-level one-to-one anchor replication`

## 3. 当前 evidence tiers

当前建议采用下面这组补充性证据分层。

### 3.1 supplementary_confirmed

这一层只保留当前最稳、最直接的 supplementary 结论：

- `architecture existence`
  `K562` 中同时观察到 `canonical backbone present = True` 与 `shift-excess present = True`
- `canonical backbone present`
  外部 context 中存在 backbone-like 结构，而不是只剩下散乱高 shift target

这两条的价值在于确认：HCC 中看到的 backbone / deviation 二元结构，并非完全局限于 HCC。

### 3.2 supplementary_supporting

这一层用于保留“方向清楚，但还不宜升格为 shared architecture claim”的结果：

- `shift-excess present`
  `K562` 中确实存在 shift-excess 结构成分，但其 dominant macro class 仍未收敛到可与 HCC 对齐的正向模块标签
- `context-specific backbone macro class`
  `K562` 的 backbone 更偏 `biosynthetic support / mitochondrial metabolism`，而不是 HCC 的 `gene expression machinery`
- `backbone-dominant architecture class`
  `K562` 当前更像 `backbone_dominant`，而不是 HCC 的 `backbone_plus_shift_excess`

这层证据说明的是：外部 replication 成立，但复现的是“结构存在性”，不是“主导生物学类别相同”。

在这一层还可谨慎加入一句：

- `stable anchor-like objects`
  `Dixit/K562` 中可观察到一部分 stable anchor-like objects，说明 target-level bridge structure 并非完全局限于 HCC 主线 context

但这句话当前只能支持：

- anchor-like structure recurrence

而不支持：

- 同一 anchors 已完成跨 context replication

### 3.3 preliminary

以下对象当前仍应保留为 preliminary，而不是被写成正式 supplementary claim：

- `K562 shift-excess macro class`
  目前仍偏 `unresolved`
- `fine-axis correspondence to HCC`
  当前没有证据支持 K562 与 HCC 在 fine-axis 层面一一对应
- `single supplementary axis naming`
  多数 K562 axis 仍来自独立聚类后的保守命名，不能直接等同于 HCC frozen axis

## 4. 当前最值得点名的 supplementary objects

如果主文档只点少数对象，建议只保留下面这些：

- 数据集层面：
  `canonical backbone present`
  `shift-excess present`
  `backbone macro class = biosynthetic support / mitochondrial metabolism`
- 轴层面：
  `unresolved_6`
  `unresolved_9`
  `unresolved_2`
  `unresolved_5`

这些 backbone-like axes 共同支持：`K562` 的 backbone 确实存在，但其主导内容更偏生物合成与线粒体能量支持，而不是 HCC 的基因表达机器主 backbone。

相比之下，`unresolved_4` 虽显示 `shift_excess` 倾向，但当前更适合作为 supporting / preliminary 之间的过渡对象，而不是可直接写成 formal positive axis。

## 5. 主张边界

`Dixit/K562` 当前**不支持**以下写法：

- `K562` 与 `HCC38 / HCC1143` 共享同一个 frozen mainline architecture
- `K562` 已完成与 HCC 对称的 axis-level formal closure
- `K562` 的 dominant shift-excess program 已获得清楚机制命名
- `K562` 的结构复现可由 `SCP542` 解释
- 虚拟扰动模型的跨 context generalization 已被证明
- HCC 中的 stable anchors 已在 Dixit 中逐一严格复现

因此，这条线最稳的主文档口径应始终是：

**supplementary replication supports architecture existence, but the dominant macro-class remains context-specific.**

## 6. 推荐写法

如果要把 `Dixit/K562` 写成一段正式结果，最稳的说法是：

`Dixit/K562` 提供了 supplementary external structure replication。当前结果显示，`K562` 中同样可以观察到 `canonical backbone` 与 `shift-excess` 两类结构成分，因此支持 architecture existence 在外部 context 中具有一定可复制性。然而，这种复现主要停留在结构层，而非主导功能类别层：相较于 HCC 中以 `gene expression machinery` 为主的 backbone，`K562` 的 dominant backbone 更偏 `biosynthetic support / mitochondrial metabolism`，而其 shift-excess 宏观类别仍未得到稳定命名。因此，当前最稳的结论是 supplementary-level architecture replication 已成立，但其 dominant macro-class remains context-specific，尚不足以将 `K562` 升格为与 HCC 并列的 primary shared architecture evidence。

若要补一句更谨慎的对象层说明，建议写成：

`Dixit/K562` 中也可观察到一部分 stable anchor-like objects，说明 target-level bridge structure 可以在独立 context 中再次出现；但这当前支持的是框架层与结构层的外部可迁移性，而不是同一 anchors 的严格跨 context replication，更不等于模型泛化能力已被证明。
